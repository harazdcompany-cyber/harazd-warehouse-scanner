HARAZD WAREHOUSE V48.1 — ПЕРСОНАЛ ТА ДОЗВОЛИ

ПОРЯДОК ВСТАНОВЛЕННЯ
1. Зробіть резервну копію сайту та бази Supabase.
2. Supabase SQL Editor: виконайте SUPABASE_V48_1_ACCESS.sql.
3. У BOOTSTRAP_FIRST_ADMIN.sql замініть YOUR_ADMIN_EMAIL на email свого існуючого акаунта Supabase Auth і виконайте SQL. Це обов'язковий крок!
4. GitHub Pages: замініть index.html, app.js, style.css. config.js не змінюйте.
5. Оновіть сайт Ctrl+Shift+R. Відкрийте «Персонал».
6. Для нового працівника спочатку створіть користувача через Supabase Dashboard -> Authentication -> Users (Invite user / Add user). Потім додайте його у вкладці «Персонал» за тим самим email.

Ролі: Адміністратор, Менеджер, Комірник, Перегляд.
Дозволи налаштовуються індивідуально; зберігаються в public.warehouse_staff.
SQL-тригери обмежують записи у equipment, categories, subcategories, warehouses, storage_locations.
Вхід без профілю не дає прав запису. Адміністратор завжди має всі дозволи.

ВАЖЛИВІ ОБМЕЖЕННЯ ПЕРШОЇ ВЕРСІЇ
- Івенти, листи пакування та ремонти ще не реалізовані: дозволи для них підготовлені, але не керують майбутніми таблицями.
- Читання вже існуючих таблиць обладнання залежить від попередніх RLS-політик; V48.1 захищає насамперед запис. Для суворого read-only за ролями потрібна окрема міграція.
- Адміністратор створює облікові записи в Supabase Auth, не з браузерного застосунку.
- Не додавайте service_role key до config.js або GitHub.
